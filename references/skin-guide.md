# 皮肤选择指南

结构与皮肤分离：结构永远来自结构文件 assets/c1～c3（伙伴云真实产品实测），皮肤只管配色和质感。

## 输入判定（拿到需求第一步）

**带样式的输入物**（带样式的 HTML、报告文件、界面设计需求、系统截图等）：
→ 向用户**二次确认**是否沿用原样式。
- 沿用：从输入物中提取色值映射到皮肤 token（见"从已有样式提皮肤"）。
- 用户要求重新设计：从皮肤库中推荐。

**不带样式的输入物**（模糊需求、会议逐字稿等）：
→ 直接向用户推荐皮肤，说清推荐理由，用户点头再动工。

推荐方式：给出你的建议＋一句话理由，不要把皮肤清单全部罗列让用户挑；文件名（hb-native / navy-gold）是内部标识，跟用户说"产品原生蓝""藏蓝金"这样的人话。

## 皮肤库

色彩气质移植自 hb-website-creator 的风格体系（S 编号对应其 design-guide）；布局、字体、材质效果不移植，示意图结构永远锁定伙伴云产品。

| 皮肤 | 文件 | 气质（对应官网风格） | 适用 | 不适用 |
|---|---|---|---|---|
| 产品原生蓝 | skins/hb-native.css | 和真实伙伴云一模一样（S2 企业专业） | 用户要求原生产品感，或业务没有品牌/行业色彩倾向时 | 需要贴合特定项目、品牌或行业气质 |
| 藏蓝金 | skins/navy-gold.css | 沉稳商务、纸感（S2/商务信任） | 通用政企/制造类商务场景；hb-digital-proposal 报告的默认皮肤 | 需要活泼、年轻或科技气质的场景 |
| 科技暗黑 | skins/tech-dark.css | 深底高对比、青色点缀（S4） | 科技/数据驱动客户、大屏气质看板图 | 嵌打印报告（深底费墨）、温暖型客户、老年受众 |
| 温暖人文 | skins/warm-terra.css | 暖陶色、米白纸感（S3） | 康养/教育/消费服务/民生类客户 | 科技企业、数据驱动产品 |
| 高端黑金 | skins/black-gold.css | 炭黑＋金、奢侈留白感（S8） | 高端精品/金融/律所/地产 | 大众消费、活泼业务 |
| 活力紫 | skins/vivid-purple.css | 明快圆润、饱和度已按 B 端压低（S9） | 年轻团队/创新/互联网 | 高端精品、权威严肃型 |
| 中式雅韵 | skins/ink-elegant.css | 黛青＋宣纸＋朱砂（S10） | 文化/茶/中医/传统手工/政务文化 | 科技产品、年轻潮流 |
| 安全红 | skins/safety-red.css | 警示红压暗一档＋微暖灰 | 消防/应急/安全生产/质量管控 | 需要轻松感的业务；主色与危险状态色同色系，见下方注意 |
| 北欧冷灰 | skins/nordic-gray.css | 冷淡低饱和蓝灰（Nord 色系，MIT） | SaaS/研发/制造等工具型客户 | 需要热情亲和感的行业；状态色警示感偏弱 |
| 柔和粉彩 | skins/latte-pastel.css | 轻快柔和（Catppuccin Latte 色系，MIT） | 教育/文创/年轻团队 | 权威严肃型、重工业；与活力紫气质相近按客户锐利度二选一 |

选型规则：
- **产品设计类也支持自定义皮肤**。产品设计类约束的是组件、结构和交互形态必须能在伙伴云中搭建，不限制只能使用产品原生蓝；配色按用户输入、项目品牌和行业气质确定。
- 没有明确样式时，不默认套产品原生蓝；先给出一款符合业务场景的皮肤建议。用户没有异议即可采用，避免把选皮肤变成冗长问答。
- 营销类按客户行业和输入物气质推荐一款＋一句理由；官网 skill 的其余风格（玻璃拟态、粗野主义、赛博朋克等）涉及材质与结构效果或 B 端不宜，不入库；确有需要时按 token 契约现造一个皮肤。
- 嵌报告的图优先和报告色系一致（有报告输入物就提色，见下节）。hb-digital-proposal 的报告皮肤与本库**同名同气质**（assets/skins/ 下同名文件）：报告已选皮肤时，配图直接用同名皮肤，不再单独推荐。

## 从已有样式提皮肤（沿用原样式 / 客户品牌色定制）

新建 `skins/<客户名或报告名>.css`，复制 hb-native.css 全量 token 后只改这些：

- `--primary` / `--primary-deep`：取输入物的主色（品牌色）；deep 取主色加深一档
- `--primary-soft` / `--primary-08`：主色 16% / 8% 透明度
- `--accent` / `--accent-bg`：营销浮层强调色，报告类输入物里找强调色（金、橙类），没有就用 `--primary-deep`
- `--banner-bg`：主色系渐变
- `--tint-*`：主色系浅底

**不要动的**：中性系（页底、卡底、灰阶文字）保持接近原生，界面才像业务系统；彩色状态 token 保持红绿灯语义（绿=成功、蓝=进行、黄=警告、红=危险、灰=未开始），只允许压饱和度去贴报告气质，不允许换语义。这两条来自设计原则（references/principles/visual-color.md）。

**主色撞状态色时怎么办**：品牌色本身就是红/绿/黄时（消防红、环保绿等），主色和状态色会混淆，用户分不清"这是品牌还是在报警"。做法是把撞车的那个状态色往深里推一档拉开距离（见 safety-red.css：主色 #C4453C，危险红 #A82920），而不是改状态语义。

## 取色尺（新皮肤的深浅关系标准）

手写或生成新皮肤时，token 之间的明暗关系不凭手感，按 Radix Colors 的 12 级语义取（每个色相从浅到深 12 级，各级有固定用途；Tailwind 色板可当默认取色库，级数换算：Radix 1-12 ≈ Tailwind 50→950 的对应梯度）：

| Radix 级 | 用途 | 对应 token |
|---|---|---|
| 1-2 | 应用背景 | --page-bg、--backdrop |
| 3 | 组件常态底 | --primary-08（选中行）、--field-bg / --filter-bg |
| 4-5 | 组件选中/按下底 | --primary-soft（选中页签）、--tint-* |
| 6-7 | 边框 | --line |
| 9 | 纯色实底（最高饱和） | --primary、--c-*（彩底标签/按钮） |
| 10 | 实底加深 | --primary-deep（顶栏） |
| 11-12 | 文字（次要/主要） | --ink-45 / --ink-85（--ink-65/25 在 11 与 12、2 与 11 之间内插） |

不在尺内、按各皮肤气质自定的：--banner-bg 渐变、--accent 强调、两个 shadow、--font。
Review 新皮肤＝逐 token 对表：选中底必须明显浅于边线、边线浅于实底、暗色皮肤同表反向套用。

## Token 契约

皮肤文件必须提供 base.css 引用的全部变量（以 hb-native.css 为准的完整清单）。少一个变量对应组件就会裸奔，新皮肤写完先拼一张列表页冒烟验证。
