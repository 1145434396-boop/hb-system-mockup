# 皮肤选择指南

结构与皮肤分离：结构永远来自结构文件 assets/c1～c3（伙伴云真实产品实测），皮肤只管配色和质感。

## 输入判定（拿到需求第一步）

**带样式的输入物**（带样式的 HTML、报告文件、界面设计需求、系统截图等）：
→ 向用户**二次确认**是否沿用原样式。
- 沿用：从输入物中提取色值映射到皮肤 token（见"从已有样式提皮肤"）。
- 用户要求重新设计：从皮肤库中推荐。

**不带样式的输入物**（模糊需求、会议逐字稿等）：
→ 给用户三个选项让其选择：推荐两套（首选＋备选，各一句理由）＋一个自定义口子（按品牌色/指定颜色现场造皮肤），用户选定再动工。

推荐方式：两套推荐各配一句话理由即可，不要把皮肤清单全部罗列让用户挑；文件名（hb-native / navy-gold）是内部标识，跟用户说"产品原生蓝""藏蓝金"这样的人话。

## 皮肤库

皮肤库分两类：**功能皮肤** 2 套（产品原生蓝、科技暗黑，服务于原生产品感与大屏气质，与报告体系无关）；**报告同名皮肤** 6 套（与 huoban-solution-report 的 assets/skins/ 同名同气质，全部为干净浅底＋清晰强调色）。

| 皮肤 | 文件 | 气质 | 适用 | 不适用 |
|---|---|---|---|---|
| 产品原生蓝 | skins/hb-native.css | 和真实伙伴云一模一样 | 用户要求原生产品感，或业务没有品牌/行业色彩倾向时 | 需要贴合特定项目、品牌或行业气质 |
| 科技暗黑 | skins/tech-dark.css | 深底高对比、青色点缀 | 科技/数据驱动客户、大屏气质看板图 | 嵌打印报告（深底费墨）、温暖型客户、老年受众 |
| 藏蓝金 | skins/navy-gold.css | 沉稳商务、纸感 | 政企、制造、工程建筑、贸易物流 | 需要活泼、年轻或科技气质的场景 |
| 北欧冷灰 | skins/nordic-gray.css | 冷淡低饱和蓝灰（Nord 色系，MIT） | 软件研发/SaaS、精密制造、工业设备、检测认证 | 需要热情亲和感的行业；状态色警示感偏弱 |
| 瑞士克莱因蓝 | skins/swiss-klein.css | 纯白网格感、单一强调色 | 咨询/专业服务、金融、设计创意 | 需要温暖亲和或活泼气质的场景 |
| 勃艮第红 | skins/burgundy-white.css | 近纯白底＋酒红，编辑杂志气质 | 高端消费、酒店餐饮、文化传媒、律所 | 科技工具型产品；主色与危险红同族，危险色已推亮拉开 |
| 晨光蓝 | skins/dawn-blue.css | 冷蓝白纸感、藏青＋活力橙 | 物流调度、救援派单、供应链、生活服务 | 权威严肃、高端精品气质 |
| 冰靛蓝 | skins/ice-indigo.css | 冷靛白纸感、亮靛蓝强调 | 互联网、电商、教育科技、创新创业 | 权威严肃、传统制造气质 |

选型规则：
- **产品设计类也支持自定义皮肤**。产品设计类约束的是组件、结构和交互形态必须能在伙伴云中搭建，不限制只能使用产品原生蓝；配色按用户输入、项目品牌和行业气质确定。
- 没有明确样式时，不默认套产品原生蓝；先给出一款符合业务场景的皮肤建议。用户没有异议即可采用，避免把选皮肤变成冗长问答。
- 营销类按客户行业和输入物气质推荐一款＋一句理由；官网 skill 的其余风格（玻璃拟态、粗野主义、赛博朋克等）涉及材质与结构效果或 B 端不宜，不入库；确有需要时按 token 契约现造一个皮肤。
- 嵌报告的图优先和报告色系一致（有报告输入物就提色，见下节）。huoban-solution-report 的报告皮肤与本库**同名同气质**（assets/skins/ 下同名文件）：报告已选皮肤时，配图直接用同名皮肤，不再单独推荐。报告体系**没有默认皮肤**，每份报告按行业推荐＋用户确认。
- 新造皮肤守住底线（与报告侧 check_skin.py 同一标准）：浅色皮肤底色近白不发黄不发浊（通道 ≥ #EC、通道差 ≤ 12、R-B ≤ 10），强调色清晰不荧光，不用米黄/大地/莫兰迪浊底。

## 从已有样式提皮肤（沿用原样式 / 客户品牌色定制）

新建 `skins/<客户名或报告名>.css`，复制 hb-native.css 全量 token 后只改这些：

- `--primary` / `--primary-deep`：取输入物的主色（品牌色）；deep 取主色加深一档
- `--primary-soft` / `--primary-08`：主色 16% / 8% 透明度
- `--accent` / `--accent-bg`：营销浮层强调色，报告类输入物里找强调色（金、橙类），没有就用 `--primary-deep`
- `--banner-bg`：主色系渐变
- `--tint-*`：主色系浅底

**不要动的**：中性系（页底、卡底、灰阶文字）保持接近原生，界面才像业务系统；彩色状态 token 保持红绿灯语义（绿=成功、蓝=进行、黄=警告、红=危险、灰=未开始），只允许压饱和度去贴报告气质，不允许换语义。这两条来自设计原则（references/principles/visual-color.md）。

**主色撞状态色时怎么办**：品牌色本身就是红/绿/黄时（消防红、环保绿等），主色和状态色会混淆，用户分不清"这是品牌还是在报警"。做法是把撞车的那个状态色推开一档拉开距离（见 burgundy-white.css：主色深酒红 #6D1F2C，危险红推亮为 #C0453C），而不是改状态语义。

## 取色尺（新皮肤的深浅关系标准）

手写或生成新皮肤时，token 之间的明暗关系不凭手感，按 Radix Colors 的 12 级语义取（每个色相从浅到深 12 级，各级有固定用途；Tailwind 色板可当默认取色库，级数换算：Radix 1-12 ≈ Tailwind 50→950 的对应梯度）：

| Radix 级 | 用途 | 对应 token |
|---|---|---|
| 1-2 | 应用背景 | --page-bg、--backdrop |
| 3 | 组件常态底 | --primary-08（选中行）、--field-bg / --filter-bg |
| 4-5 | 组件选中/按下底 | --primary-soft（选中页签）、--tint-* |
| 6-7 | 边框 | --line |
| 9 | 纯色实底（最高饱和） | --primary、--c-*（彩底标签/按钮） |
| 10 | 实底加深 | --primary-deep（顶栏） |
| 11-12 | 文字（次要/主要） | --ink-45 / --ink-85（--ink-65/25 在 11 与 12、2 与 11 之间内插） |

不在尺内、按各皮肤气质自定的：--banner-bg 渐变、--accent 强调、两个 shadow、--font。
Review 新皮肤＝逐 token 对表：选中底必须明显浅于边线、边线浅于实底、暗色皮肤同表反向套用。

## 壳层主题（顶栏与左列的配色关系）

官方支持四种布局，皮肤只出颜色，布局由 `.window` 上的类决定：

| 类 | 长相 | 用在哪 |
|---|---|---|
| `theme-band` | 顶部整条同色：左列顶部 56 与右侧顶栏都是 `--primary-deep`，侧栏其余白 | 默认，配色最醒目，营销图首选 |
| `theme-side` | 整个左列 `--primary-deep`，右侧顶栏白 | 想让导航成为主视觉时 |
| `theme-full` | 整个左列 `--primary-deep`，右侧顶栏 `--primary`（浅一档） | 品牌色饱和度低、需要更大面积着色时 |
| `theme-light` | 全浅：左列与顶栏都是白底 | 贴合真实产品默认观感的产品设计类图 |

左列 248 宽是通顶的，顶部 56 与右侧顶栏同色时中间不能出现竖线（`.side::after` 已把右边线从 56 起画）。

## Token 契约

皮肤文件必须提供 base.css 引用的全部变量（以 hb-native.css 为准的完整清单）。少一个变量对应组件就会裸奔，新皮肤写完先拼一张列表页冒烟验证。

**--backdrop 现为备用 token**：画布已改透明，衬底不再绘制；token 保留以维持契约完整。
