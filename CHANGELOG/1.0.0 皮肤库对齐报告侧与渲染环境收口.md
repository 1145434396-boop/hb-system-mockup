# 1.0.0 皮肤库对齐报告侧与渲染环境收口

> 2026-08-26

0.3.3 之后还有两笔渲染环境的收尾改动未记录；更早的 2026-08-21 那轮皮肤库重构整个漏记了，导致 0.1.0 里那份「10 套皮肤」清单一直挂着过期信息。本版把这两处补齐并定为正式发布版：结构资产、皮肤体系、检查管线、渲染环境四块都已稳定，与 huoban-solution-report 的联动口径也已对齐。

## 摘要

1. 优化: 皮肤库整个换了一轮——淘汰 6 套旧皮肤、新增 4 套与报告同名的，现在是「6 套报告同名 + 2 套功能皮肤」共 8 套，报告选了哪套皮肤配图就用同名的那套（**补记 2026-08-21 的改动**）
2. 修复: 0.1.0 里列的 10 套皮肤名单早已作废，本版起以皮肤目录为准
3. 优化: 不再有"缺省就套某一套"的皮肤，改为每次主动推荐一款并说明理由，用户没异议就用——既不让一批图全是同一个色，也不把选皮肤拖成一轮问答
4. 修复: Linux 沙箱下载 Chrome 改为 npmmirror 优先、googleapis 兜底，国内网络不再卡在下载这一步
5. 优化: 装 Chrome 的一键脚本删掉，改为文档里给裸命令手动引导

## 详情

### 1. 优化: 皮肤库与报告侧对齐

补记 2026-08-21 的改动。此前图侧和报告侧各有一套皮肤，名字对不上，报告选定皮肤后配图只能靠"气质接近"去凑。

**改前**（0.1.0 起沿用的 10 套）：产品原生蓝、藏蓝金、科技暗黑、温暖人文、高端黑金、活力紫、中式雅韵、安全红、北欧冷灰、柔和粉彩。

**改后**（8 套，分两组）：

| 分组 | 皮肤 | 用途 |
|---|---|---|
| 报告同名（6 套） | `swiss-klein` `burgundy-white` `dawn-blue` `ice-indigo` `navy-gold` `nordic-gray` | 与 huoban-solution-report 的 `assets/skins/` 同名同气质，报告选定哪套，配图用同名那套，报告与图自动同色系 |
| 功能皮肤（2 套） | `hb-native` `tech-dark` | 不进报告配色体系：前者是产品原生蓝，用于"就是要长得像伙伴云本身"的场景；后者是暗色，用于大屏与暗色演示 |

删除的 6 套：`black-gold` `ink-elegant` `latte-pastel` `safety-red` `warm-terra` `vivid-purple`——报告侧已淘汰，图侧留着只会让两边再次错位。新增的 4 套按 token 契约与 Radix 12 级取色尺生成。

`skin-guide.md` 同步重写：皮肤库分功能/报告同名两组、补行业分工表、给推荐两套并留自定义口子、写明新皮肤的干净底线。

### 2. 修复: 0.1.0 的皮肤清单作废

0.1.0 那份文件里"10 套皮肤"及其名单是当时的事实，现已全部失效。历史记录不改写，此处声明：**皮肤以 `assets/skins/` 目录为准**，任何文档里的皮肤清单如与目录不符，以目录为准。

### 3. 优化: 皮肤选法从"有缺省"改为"主动荐一款"

**改前**：`navy-gold` 带默认标注，用户没指定时套它。

**改后**：`navy-gold` 的默认标注去掉，`skin-guide.md` 里定的规则是：

> 没有明确样式时，不默认套产品原生蓝；先给出一款符合业务场景的皮肤建议。用户没有异议即可采用，避免把选皮肤变成冗长问答。

两头都要避：有缺省会让一批图全是同一个色，皮肤体系形同虚设；每次都摊开清单让用户挑，又把出图拖成一轮问答。所以是"荐一款 + 给理由 + 不反对就用"。

报告侧的口径同理——报告体系没有默认皮肤，每份报告按行业推荐再由用户确认；报告已选定皮肤时，配图直接用同名皮肤，不再单独推荐。

### 4. 修复: Chrome 下载源改为 npmmirror 优先

0.3.3 把内置的 Chrome 分卷移除、改成按需下载后，Linux 沙箱里从官方 CDN 拉 `chrome-headless-shell` 经常卡住。

**改后**：下载源顺序改为 **npmmirror 优先、googleapis 兜底**，两个源都失败才报错并给出手动引导。`check.py` 的探测链路不变（`CHROME_BIN` → 本机 Chrome → 已解压目录 → `PATH` → 按需下载缓存到 `~/chrome-headless-shell-linux64/`），macOS 仍走本机 Chrome、行为不变。

### 5. 优化: 删除一键安装脚本

**改前**：`scripts/get_chrome.sh` 一键装。

**改后**：脚本删除，`references/chrome-env.md` 里只留裸命令供手动执行。一个只在特定沙箱环境下才用得上的 shell 脚本，维护成本高于它省下的那一步；文档里给命令，需要的人自己跑。
