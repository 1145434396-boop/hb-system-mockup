# 1.1.0 按需加载改造

目标：模型只读当前任务真正需要的规则和组件，固定资产交给脚本处理；真实产品约束、实测尺寸与验证闭环不变。

## 入口

- `SKILL.md` 收紧为：路由表、原则加载表、六步流程、硬约束、落点。详细规则全部下沉到按需引用文件，同一规则只保留一个真相源。
- 新增「设计原则路由」表：principles 按任务类型读，不再整目录读（普通列表页不读看板专用判据）。

## 引用文件拆分

- `references/skin-guide.md` 拆为 `references/skin/routing.md`（每次执行读：输入判定、皮肤库、壳层主题）和 `references/skin/custom-skin.md`（仅提色值/新造皮肤时读：token 映射、撞色处理、Radix 取色尺、底线、契约）。
- `references/canvas-spec.md` 拆为 `references/canvas/` 四份：`product-design.md`、`marketing.md`（步骤 2 按用途二选一）、`verify-export.md`（步骤 6 读：验证清单＋2x PNG 导出）、`report-embed.md`（仅嵌报告时读：SVG/foreignObject 三必修点）。

## 新脚本

- `scripts/extract_templates.py`：按 `data-architecture`／`data-component`／`data-group` 从 c1～c4 精确提取模板，自动带文件头说明、前置注释和全部 data-* 属性（含 data-measured）；名字不存在直接报错并列出可用名；`--list` 打印目录。结构正本仍只有 assets/c1～c4 一份，脚本只读不写。
- `scripts/build.py`：确定性组装单文件 HTML，固定顺序拼皮肤 → base.css → 本图补充样式 → icons.svg → 内容 → fit.js；模型只写 `.stage` 内容和补充样式。改过公共资产后重跑即可重拼既有图。

## 效果

- 列表页场景结构读取从整读 c2（约 12.5k 字符）降到按需提取（约 2.4k 字符）。
- 典型任务前置加载约降一半；最终 HTML 里的固定壳不再由模型逐字生成。
